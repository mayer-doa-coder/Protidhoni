# Datasets

Each JSONL record has `text` and a frozen report `type`. The training command
requires at least four training records and one evaluation record for every
frozen type.

## `smoke_train.jsonl` / `smoke_eval.jsonl` — pipeline smoke corpus

This deliberately tiny corpus verifies the local BanglaBERT fine-tuning
pipeline, its label checks, and metrics output only. Every sentence is
synthetic; it is **not** crisis data, independently reviewed data, a
benchmark, or suitable for deployment. The resulting checkpoint must never be
configured as `PROTIDHONI_FINE_TUNED_MODEL_PATH`.

## `crisis-training.jsonl` / `crisis-evaluation.jsonl` — hand-authored demo corpus

240 training / 64 evaluation examples (30/8 per frozen type), split roughly
evenly across Bangla script, English, and Banglish (romanized code-switched)
registers, covering common Bangladesh crisis scenarios (flood, cyclone, fire,
landslide, road/bridge hazards, medical emergencies, shelter and relief
logistics, evacuation instructions).

**Provenance, stated plainly:** every sentence was hand-written for this
project by an AI assistant (Claude) at the user's request, generated by
`../../../scratchpad` tooling during that session — none of it is scraped,
downloaded, or sourced from real incident reports, social media, or any other
external corpus. It is synthetic practice data, not independently reviewed or
consented real crisis text.

This is large enough to produce a real (non-trivial) BanglaBERT fine-tune for
a hackathon demo, and is a legitimate step up from the smoke corpus — but it
is **still not** a substitute for reviewed, consented, representative
real-world data. Before relying on this classifier for anything beyond a
demo, replace this corpus with separately reviewed, consented, representative
data stored in the team's approved private location, keep a held-out
evaluation set, document its review, and evaluate per class as well as
overall accuracy and macro-F1.
